# Security review: CNTR repository and app (2026-10-27)

Scope: the public GitHub repository `ITMERowe/CNTR` (working tree and full history of all branches, 3.2 M lines of diffs), the CI workflow, and the Android app (manifest, Capacitor config, web code, backup and CSV handling, dependencies). Read-only: nothing was changed.

**Bottom line:** no API keys, passwords, tokens or signing keys are in the repository or ever were. The findings are about personal data in a public repo, one privacy statement that is not accurate, and defence-in-depth gaps in the app.

## Findings, most serious first

| # | Severity | Finding | Suggested fix |
|---|---|---|---|
| 1 | Medium | **Your personal Gmail address is the author of 80 commits** in a public repository. Anyone can read it with `git log`, and scrapers collect such addresses for spam. | Use your GitHub no-reply address for all future commits (`git config user.email 38850947+ITMERowe@users.noreply.github.com`) and turn on GitHub → Settings → Emails → *Keep my email address private* and *Block command line pushes that expose my email*. Rewriting the old commits is possible but destructive (every commit hash changes, forks and clones keep the old ones), so not recommended. |
| 2 | Medium | **The privacy text is not accurate.** About → Privacy says *"Everything you record stays on this phone"*, but `android:allowBackup="true"` lets Android Auto Backup copy the app's data (including the SQLite database) to the user's Google Drive. This matters for the Play Store privacy policy and Data safety form. | Either keep Auto Backup (your earlier choice) and change the text to say Android may back the data up to the user's own Google account; or turn it off (`allowBackup="false"`). Keeping it and fixing the text is the smaller change and keeps a safety net. |
| 3 | Low | **No Content-Security-Policy.** If text ever got rendered as HTML by mistake, nothing would stop a script from running or sending data out. Today no such path exists (finding-free check below), so this is defence in depth. | Add a CSP `<meta>` to `index.html`: scripts and connections only from the app itself, no outside network. Test on the phone, since Capacitor's own bridge must still work. |
| 4 | Low | **CSV formula injection.** A product or event name starting with `=`, `+`, `-` or `@` is written to the CSV as is, so Excel or Sheets runs it as a formula (for example a `=HYPERLINK(...)` that leaks data when clicked). Most likely through a restored backup someone else made. | In `csvCell`, put a `'` in front of text cells that start with `=`, `+`, `-`, `@`, tab or carriage return (numbers are left alone). |
| 5 | Low | **The INTERNET permission is still declared** although the app never uses the network. Removing it makes "never uses the internet" enforced by Android itself, and shows as no network access on the Play listing. | Remove `<uses-permission android:name="android.permission.INTERNET" />` (you chose to keep it earlier; this is the security reason to reconsider). Check backups, share sheet and restore still work on the phone. |
| 6 | Low | **File sharing scope is wider than needed.** The FileProvider shares `external-path "."` (all of shared storage) and the whole cache. It is not exported and only grants access to the file the app shares, so the risk is small. | Narrow `file_paths.xml` to `Documents/CNTR` and the cache folder the app writes to. |
| 7 | Low | **CI hardening.** The workflow has no `permissions:` block, so its token gets the repository's default rights; the third-party `android-actions/setup-android@v4` is pinned by tag, not by commit; if the release build fails, the step stops before deleting the decoded keystore (the runner is thrown away afterwards, so it is not left anywhere). | Add `permissions: contents: read`; pin third-party actions to a commit SHA; delete the keystore in a `trap`. |
| 8 | Info | **No size limit on names in a backup**: a restored backup can contain a 10 MB product name (accepted in 83 ms). It can only slow down the phone that restores it. | Optional: reject names over, say, 200 characters in `parseBackup`. |
| 9 | Info | Your Windows user folder path (`C:/Users/User/...`) is in 3 tracked files (`.claude/settings.json`, `.codex/hooks.json`, `HANDOFF.md`). The user name "User" is generic, so this reveals almost nothing. | None needed. |
| 10 | Info | In a public repo, CI artifacts (the release-signed APK and `.aab`) can be downloaded by any signed-in GitHub user. That is fine for an app that will be public, but test builds are visible too. | None needed, or make the repository private before sharing test builds you do not want public. |

## Checked and fine

- **Secrets**: no API keys, tokens, passwords, private keys, keystores (`.jks`, `.keystore`, `.p12`), `.env`, `google-services.json` or `local.properties` anywhere in history. Mentions of "secret" and "password" are documentation of the secret *names* only. The signing key lives outside the repo (`C:/Users/User/CNTR-signing`); `.gitignore` blocks keystores, `keystore.properties` and `.env`.
- **CI secrets**: used only in the Build APK step, never printed; the workflow runs on pushes only (no `pull_request` / `pull_request_target`), so pull requests from forks never get the secrets; without them CI builds a debug APK.
- **Dependencies**: `npm audit --omit=dev` → 0 vulnerabilities.
- **HTML injection (XSS)**: product, event and expense names are rendered by Preact, which escapes text. The only `innerHTML` is the tutorial bubble, with fixed text. No `eval`, `new Function` or `document.write`.
- **Hostile backup files**: files over 50 MB are refused before parsing; 100 000-deep nesting is rejected with a normal "damaged" message; a `__proto__` key does not pollute objects; every record is validated before anything is replaced, and a safety copy is saved first.
- **Android**: only the launcher activity is exported (required); the FileProvider is not exported; no cleartext-traffic or debuggable flags; no dev `server.url` in the Capacitor config; data is in app-private SQLite.
