# CNTR 0.1 Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Security review, three bug fixes, a light theme and an Indonesian translation for CNTR 0.1.

**Architecture:** Fixes are local edits in `state.ts`, `main.ts` and `EventScreen.tsx`. The theme is a second set of CSS tokens chosen by a `data-theme` attribute on `<html>`. The translation is one dictionary module (`src/i18n.ts`) with a typed `t()` and `data-i18n` attributes for static markup; dates take the app's locale.

**Tech Stack:** TypeScript, Preact, Vite, Capacitor 8 (Android, SQLite store), Node test runner (`npm test`), Playwright browser suites (`npm run test:e2e`).

**Spec:** `docs/superpowers/specs/2026-10-27-0.1-update-design.md` (approved 2026-10-27). Read it with this plan.

## Global Constraints

- Version names stay `0.1.<build>`; no version change in this plan.
- Offline only; no new network use. No new runtime dependency unless clearly smaller than the code it replaces.
- Old data, settings and backups load unchanged; no data format change.
- Text contrast ≥ 4.5:1 in both themes (3:1 for large text, 2.6:1 for tile text, as the layout suite already allows).
- Not translated: user-typed text, payment method names (Cash, QRIS, Transfer, Card, E-wallet), CSV column headers.
- Number formats stay tied to the currency setting; only month names follow the app language.
- Security fixes only after the owner has read the report and agreed.
- Before each commit: `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run test:e2e` all pass; then `graphify update .`. Never commit `.claude/settings.json`, `.claude/skills/playwright-cli/`, `.playwright/`.
- The e2e runner serves `dist/` on port 4320: rebuild before running it.

## Review Focus

1. A product deleted and then re-created with the same name: old sales show under the new product and keep their old prices (no repricing).
2. Theme "Phone setting" while the phone switches dark↔light with the app open: the app follows without reload.
3. Updating user with data but no `language` saved, on an Indonesian phone: stays English (the most likely mistake is treating them as a fresh install).
4. Indonesian UI with long translations: no overflow or cut-off buttons at 360 px width (the layout suite run in `id`).
5. A deleted product's sales in History/Compare/payment mix: they render with a neutral colour, never a blank or crash.

Each is pinned by a test in the owning task (Tasks 2, 5, 6, 7, 2).

**Interfaces:**
- Produces, in `src/i18n.ts` (no DOM or storage imports, so Node can test it):
  - `type Lang = 'en' | 'id'`
  - `const en: Record<string, string>` and `const id: Record<keyof typeof en, string>` (TypeScript errors if `id` misses a key)
  - `type Key = keyof typeof en`
  - `setLanguage(lang: Lang): void`, `language(): Lang`
  - `t(key: Key, params?: Record<string, string | number>): string`: `{name}` placeholders replaced from `params`
  - `locale(): string`: `'en-GB'` for `en`, `'id-ID'` for `id`
  - `initialLanguage(phoneLanguage: string, isFreshInstall: boolean): Lang`: `'id'` only if fresh and `phoneLanguage` starts with `id`
  - `translateStatic(root: ParentNode): void`: sets `textContent` of every `[data-i18n]`, and `aria-label`/`title`/`placeholder` from `data-i18n-aria` / `data-i18n-title` / `data-i18n-placeholder`
- Language load rule (in `storage.ts` `loadSettings`): a stored `language` wins; else `initialLanguage(navigator.language, fresh)` where `fresh` = no data key and no `cntrMeta.tutorialOffered` in the store at startup; the result is saved once so it never changes on its own.
