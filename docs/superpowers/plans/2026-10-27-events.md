# Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Reports and Event screens with one always-live Event screen that supports multi-day events, and turn History into a list of past events that can be viewed, compared (two at a time) and edited.

**Architecture:** The live event reuses the existing `cntrSales` and `cntrEventCosts` keys as its sales and expenses, plus one new key `cntrLiveEvent` for its name and day breaks. That makes the live data's "migration" free: nothing is copied. Past events live in a new key, `cntrEvents`. Old saved reports and the imported event are no longer read (D1). All event maths go in a new pure module, `src/events.ts`, which Node tests directly. Storage writes made in the same tick go into one all-or-nothing batch, so End event (which writes events, sales, costs and meta together) can never be half-applied.

**Tech Stack:** TypeScript, Preact, Vite, Capacitor 8 (SQLite kv store); tests use `node --test` and playwright-core browser suites.

**Spec:** `docs/superpowers/specs/2026-10-27-events-design.md`

## Global Constraints

- Offline only; no new runtime dependency.
- VS Code-dark palette and tokens in `src/style.css`; original product colours; 44px tap targets; no horizontal overflow at 320/360/412px and 892×412 landscape.
- Net profit everywhere = product profit (revenue − product cost) − expenses.
- Day card profit = that day's product profit, before expenses.
- Compare = exactly two events.
- End day and End event each ask "are you sure?" first; End event and every saved History edit or delete take an automatic backup first (the existing `withAutoBackup`).
- Sell tab (tiles, hero, undo) shows **today's** sales only: the sales after the last day break.
- Android back steps back through every new screen and sheet (the existing `goBack()` handles `.back-btn` and `[id$="CloseBtn"]`).

## Review Focus

1. **App killed during End event:** it must leave either the old state or the new one, never both, and never lose sales. Test: a unit test where a batch write fails. Neither the events nor the sales key changes.
2. **Undo on Sell right after End day:** the counter shows 0 and undo says "Nothing to undo"; a frozen day's sale is never removed. Test: e2e in Task 5.
3. **Restore an old (1.0.21) backup:** its live sales and expenses come back as the live event; saved reports are ignored without an error. Test: unit test in Task 2.
4. **History edit cancelled:** Cancel or Android back while editing leaves the stored event unchanged. Test: e2e in Task 6.
5. **Deleting or renaming a product with sales in a past event:** past events keep their own product snapshot (name, colour, price), so they still render. Test: e2e in Task 6.

### Task 1: Event maths and atomic batches

**Files:**
- Create: `src/events.ts`
- Modify: `src/types.ts` (add `LiveEventMeta`, `PastEvent`; later tasks delete `SavedReport`, `ImportedEventReport`, `EventView`, `ReportType`)
- Modify: `src/storage.ts` `flush()` (group same-tick writes)
- Test: `tests/events.test.ts`; add it to `npm test` in `package.json`

**Interfaces (Produces):**
- `interface LiveEventMeta { id: string; name: string | null; startedAt: string; dayBreaks: string[] }`. A `name` of null means "use the default name".
- `interface PastEvent { id: string; name: string; startedAt: string; endedAt: string; dayBreaks: string[]; products: Product[]; sales: SaleRecord[]; expenses: EventCost[] }`
- `splitDays(sales: SaleRecord[], dayBreaks: string[]): SaleRecord[][]`. Returns `dayBreaks.length + 1` arrays; a sale belongs to the first day whose break is after its timestamp.
- `todaySales(sales, dayBreaks): SaleRecord[]`. The last element of `splitDays`.
- `eventSummary(sales: SaleRecord[], expenses: EventCost[]): { revenue; productProfit; expenses; net; count }`, where net = productProfit − expenses.
- `defaultEventName(sales: SaleRecord[], now: Date): string`. Returns `` `Event ${date}` ``, where date is the first sale's date or `now`, formatted with `toLocaleDateString([], { day: 'numeric', month: 'short', year: 'numeric' })`.
- `snapshotProducts(sales: SaleRecord[], known: Product[]): Product[]`. One product per sold name. It uses `known`'s colour and the latest sale's price/cost; unknown names get colour `''`.
- `adjustCount(event: PastEvent, day: number, product: string, payment: string, delta: 1 | -1): PastEvent`. Returns a new event. +1 adds a sale priced like that product's latest sale on that day, otherwise like its snapshot product, timestamped 1 ms before that day's end break (or 1 ms after the last sale of the event for the last day). −1 removes the latest matching sale on that day, or returns the event unchanged if there is none.
